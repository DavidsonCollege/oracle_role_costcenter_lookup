Search Index Rebuild (after a refresh)

Use only after a Prod-to-Test refresh of a non-Prod instance. Don't run this after quarterly updates: Oracle reingests changed indexes itself during updates. It never runs against Production. It submits the index ingest job for each index one at a time, waits for each to finish, then runs Compute Users ACL, the Learning ACL job and the three Recruiting index jobs. It stops at the first error or warning and alerts the team. Uses the environment, username and password above; your account needs the privilege to submit these jobs.

Your config differs from the one shipped with this version of the app. Your copy is what the app uses. If you didn't change it on purpose, replace it so you get the latest step list and job settings.

    Your current copy is saved as a backup first.
    Turn off while testing so the channel only gets real runs. Alerts still show in the app.

    Slack alerts (#team-admin-services-private)

    1. In 1Password, open Slack webhook – Search Index Rebuild alerts and copy its credential (a URL starting with https://hooks.slack.com/services/). If you can't see that item, ask for access to it.
    2. Paste it below and click Save, then Send test and check that the message arrives in #team-admin-services-private.

    Do this once on each computer you run rebuilds from. The URL is saved encrypted on this computer and stays through app updates. Don't paste it in chat, email or tickets.

    Check index list (after the Production quarterly update)

    Choose Production at the top, then click Check index list. Read-only. The app finds Oracle's latest reindex request (FndOSCSReindexJob, submitted by FAADMIN), reads the list of indexes in its log and compares it with the rebuild's step list and exclusion list.

    Inspect a request (read-only; works on any instance)

    Enter an Oracle scheduled process request ID to see its status, parameters and log without changing anything. Use it to find out why a rebuild step stopped, or to read the parameters a past run used, including on Production. It shows the start and end of long logs, and each box has a Copy button.

    Credentials are never stored. All requests are made securely via the desktop app — no browser CORS restrictions.
